## Problem

The starting point was a V1 product that worked but was entirely dependent on a single external vendor: 100% of its intelligence — generation, embeddings, everything — ran through Gemini's API, with no fallback and no path to running on infrastructure the organization controlled. That's a fragile place to build a legal product from: every cost increase, rate limit, policy change, or outage at the vendor becomes the product's outage, and no enterprise or government legal customer with real data-residency or air-gap requirements can be sold a tool where every document leaves the building. The goal was to take that V1 system and turn it into a fully self-hosted legal-AI platform — one where a customer could run the entire stack, including large-model generation, on their own hardware with zero external API calls — without ever taking the product offline or breaking the endpoints existing users depended on.

## Why It Was Hard

The obvious move — "just self-host everything at once" — was never viable. Large-language-model generation, embeddings, reranking, OCR/vision, NER, coreference, and NLI faithfulness checking each have wildly different hardware profiles, and a legal-document product can't ship a half-working version of any of them: a fabricated citation or a missed obligation clause is a liability problem, not a UX bug. Complicating that, the actual development hardware had no discrete GPU for a meaningful stretch of the build, which forced an honest choice between faking capability with commercial APIs or building genuinely CPU-only equivalents for every pipeline stage — segmentation, entity extraction, clause classification, coreference — and being explicit about which parts were placeholders versus production-grade. On top of that, the system had to stay provider-agnostic by construction, not by convention: it's easy to say "we could swap the LLM provider" and much harder to enforce it so that a stray import of a vendor SDK anywhere outside one package fails CI. And the whole migration had to run underneath a live product — every phase had to leave V1's endpoints serving real traffic while V2 capability was built and cut over incrementally, which ruled out any big-bang rewrite.

## Approach

The build was sequenced so that architecture came before hardware, and every dependency was removed in the order it was actually removable. First, the data and service foundation (Postgres, Redis, org-scoped auth, document persistence) was stood up without touching user-facing behavior, and a thin Model Router pass-through was introduced early — deliberately scoped small so it could later become the real provider-agnostic seam without being torn out. Next came the structured-understanding pipeline: every stage that turns raw text into a structured clause graph (segmentation, entity extraction, deontic tagging, temporal normalization, clause classification) was built as a genuine, tested CPU-only implementation rather than an LLM call in disguise, with GPU-dependent upgrades explicitly deferred rather than faked. A knowledge graph and hybrid dense+sparse RAG layer followed, backed by a real cited-source corpus instead of a hardcoded knowledge base, with a fabricated-citation validator built in from the start. Agentic orchestration then wired those pieces into a fixed, auditable pipeline with a citation check and KG-consistency check on every claim before it reached a user.

Only after that foundation was solid did the project turn to removing the external dependency itself, and it did so in the cheapest-to-hardest order: everything that could run on CPU (embeddings, reranking, ASR, TTS, a small local LLM for dev) was self-hosted first, behind a declarative routing policy that classified every call by task, sensitivity, and capability rather than by vendor — with an import-linter CI rule making it structurally impossible for a commercial SDK to sneak in outside the provider package. GPU acquisition was treated as one pivotal, deliberately late unlock rather than a starting requirement: a single rented or owned GPU pool made self-hosted large-model generation, vision-based document understanding, and every planned fine-tune (NER, clause classification, the NLI faithfulness head) possible at once, and each cutover to a self-hosted model was A/B-gated against the existing Gemini baseline before it was allowed to become the default — nothing was assumed better just because it was self-hosted. With generation self-hosted, packaging work made on-prem and air-gapped deployment a supported profile rather than a heroic one-off: signed model artifacts, SBOM allowlists that fail a build if a vendor SDK is present, and a collapsed single-node data layer for smaller installs. The final layer added portfolio-level intelligence — in-house trained models, cross-document consistency and simulation agents — deliberately last, since it depended on training infrastructure that didn't exist until the GPU phase landed.

## Results

The end state is a product where every core legal task — document rewrite, structure and timeline extraction, Q&A, risk analysis, contextualized research, and verification — is served by a self-hosted model that has been measured to meet or beat the original commercial baseline on its own evaluation suite, with the commercial provider demoted to an optional, explicitly-enabled escalation rather than the default path. A contributor or customer can run the entire product with zero API credentials and zero external network calls, from the embedding and reranking layer up through generation. The same codebase now supports four real deployment profiles — cloud, hybrid, on-prem, and fully air-gapped — validated against actual pilot installs rather than left as a roadmap aspiration, and the eval-gate and routing-policy logging mean every model-selection decision is auditable after the fact, not just at design time. Throughout the entire migration, V1's endpoints kept serving live traffic; the cutover was continuous rather than a rewrite-and-replace.

## What Broke

A silent, load-bearing bug surfaced during the RAG buildout: V1's default embedding model had been quietly 404ing against the current API version, which meant dense retrieval had effectively been running as BM25-only for an unknown stretch of production time without anyone noticing — a good reminder that "the retrieval feature works" and "the retrieval feature is doing what you think it's doing" are different claims that need different verification. The dev-hardware GPU gap forced a harder-than-planned mid-project re-plan of the entire structured-understanding phase, since several pipeline stages that were assumed to need a model turned out to need a genuinely separate CPU-native implementation, not just a smaller model — that cost real time but produced a more honest, better-tested pipeline than the original plan would have. The verifier's faithfulness check shipped for a long stretch as an explicitly-labeled lexical-overlap stand-in rather than real NLI, which was the right tradeoff for shipping continuously but meant living with a known-weaker safety net until GPU capacity arrived. And several large workstreams — a durable execution engine, the memory service, the entire frontend SPA and agent trace viewer — were deliberately pushed out of earlier phases they were originally scoped into, which kept each phase shippable but meant the backend ran ahead of any UI for longer than the original roadmap intended.

## Stack

Postgres and Redis for the core data and session layer; Memgraph for the knowledge graph, with pgvector/pgvectorscale and Apache AGE/KùzuDB as collapsed-data-layer substitutes for on-prem profiles. LangGraph for agent orchestration, DBOS (with Hatchet/Temporal at larger scale) for durable execution. A custom `ModelProvider` protocol splitting self-hosted (`providers-core`) from commercial (`providers-external`) adapters, enforced by an import-linter CI contract, with a declarative YAML routing policy driving provider/model selection by task, sensitivity, and budget. Self-hosted serving via vLLM/SGLang running Qwen3-32B (quantized) as the default generator, Qwen3-4B/8B for constrained profiles, DeepSeek-R1-Distill/QwQ-32B for flagged-hard reasoning tasks, and Qwen2.5-VL for scanned-document understanding; TEI/Infinity serving self-hosted embeddings (EmbeddingGemma/BGE-M3) and a bge-reranker for retrieval; faster-whisper and Kokoro/Piper for ASR/TTS; Ollama for the zero-credential local-dev default. Fine-tuning via Unsloth on InLegalBERT/ModernBERT for NER and clause classification, GLiNER and maverick-coref for entity typing and coreference, distilabel for weak-supervision-then-distill teacher/student training. Docling, Table Transformer, and olmOCR/Qwen2.5-VL for layout, table, and OCR extraction. Inspect AI (with promptfoo for prompt regression) as the eval backbone against LegalBench, CUAD, ContractNLI, and MAUD, gating every merge and every self-hosted cutover. Zarf, OpenTofu, Harbor, and KitOps ModelKit for air-gapped packaging and signed model distribution, with cosign/Syft/Trivy for supply-chain verification, and k3s for the smaller on-prem target. Next.js and TypeScript for the frontend SPA, generated from the OpenAPI schema, with Yjs for collaborative negotiation editing. LightGBM for the risk-scoring model, MLflow and DVC for model registry and data versioning, and Argilla for legal-expert review of training data.
